# Table metadata and structural-label cleanup plan

Date: 2026-08-14

Status: implemented and verified on the synthetic suite and private corpus.

## Goal

Remove renderer-authored frame/header/footer labels from ordinary converted
content, suppress structurally empty page furniture, and replace the broad
`Unsupported table fields` body marker with bounded typed table metadata.
Unknown or malformed structures must remain visible and every uninterpreted
source value must remain available in JSON/diagnostics.

## Evidence gathered before implementation

- The private corpus contains 373 table frames. Every table definition has nine
  integer fields, every one of the 3,112 row records has seven, every one of the
  973 column records has five, and all 13,099 cell headers have twelve.
- The existing parser reports 369 visible `table fields` objects because it
  treats all fields other than cell row/column coordinates as one opaque class.
  Four additional table frames have no materializable cell grid.
- In `mydocs/6e.sam`, the reported 80 field sets are exactly one table
  definition, seven row definitions, nine column definitions, and 63 cell
  headers. The frame is a 7-by-9 table, not 80 unrelated unknown records.
- The reference field order describes table dimensions/default geometry,
  per-row height/gutter/flags, per-column width/gutter/flags, and cell flags,
  joined-row/joined-column counts, shading, borders, content flags, and
  protection. Corpus shapes add two stable table-definition tail values and
  three cell-header tail values whose meanings are not corroborated.
- Connected-cell records use flag `0x100` on an anchor (usually together with
  `0x80`) and positive joined-row/joined-column counts. Covered member records
  use `0x80` with relative coordinates. The existing renderers already support
  bounded row/column spans, but applying this mapping must not shift covered
  cells into new columns.
- There are 396 empty footers and 287 empty headers in the corpus. They carry
  no readable content, yet fallback renderers can emit labels such as
  `[Header: odd/right pages]`.
- There are 967 structurally known frames and one frame with unknown structure.
  Known frame labels are generated by renderers; frame structure and geometry
  already remain in typed JSON.

## Design

1. Append bounded table metadata fields to the public IR without changing
   existing positional constructor arguments. Preserve raw/internal tails as
   integer tuples rather than assigning meanings.
2. Parse only exact canonical record shapes atomically. A malformed value,
   duplicate definition, out-of-range coordinate, unknown subsection, or
   unexpected tail shape keeps the existing visible fallback and strict-loss
   behavior.
3. Materialize documented row/column dimensions and flags. Derive column
   proportions from width plus gutter and normalize them to the renderer's
   actual container instead of assuming source absolute coordinates fit the
   destination page.
4. Apply header-row flags and independently corroborated cell alignment. Apply
   connected-cell spans only when the anchor rectangle is in bounds and every
   covered source member agrees with it; otherwise preserve an ordinary grid
   and diagnose the unresolved merge.
5. Retain shading, border, protection, reserved fields, and undocumented tails
   in typed IR. Do not invent colors, border styles, edit restrictions, formula
   results, or row heights that could clip content.
6. For an exact canonical table, remove the body `Unsupported table fields`
   object. Emit a coalesced semantic diagnostic when retained fields are not
   rendered; raw frame data and typed JSON remain complete.
7. Make structural frame/header/footer labels opt-in through renderer option
   `show_structure_labels` and CLI flag `--show-structure-labels`. By default,
   known containers render their nested content without labels; empty
   furniture renders nothing. Nonempty unknown/invalid structures remain
   visibly labelled regardless of the option.
8. Keep annotation, footnote, missing-asset, malformed-content, recursion,
   safety-limit, and genuine `UnsupportedObject` markers unchanged.

## Adversarial review and guardrails

- A cleaner page is not evidence of full table fidelity. Unsupported styling
  remains a semantic diagnostic even when it moves out of document content.
- Declared row/column counts are untrusted. Existing parser and renderer cell,
  row, column, record, integer, and output limits still win.
- Do not use undocumented table/cell tail values as colors, margins, or line
  widths. Their stable shape establishes preservation, not semantics.
- Do not mark the first row as a header merely because it is first when a
  canonical row-definition record explicitly says otherwise.
- Do not apply a merge from one flag alone. Validate its dimensions, bounds,
  covered coordinates, and conflicts before changing the logical grid.
- Renderer table widths must be normalized against an explicit body/cell
  container and retain minimum usable widths. Hostile manual IR continues to
  fall back visibly rather than raising or allocating an oversized grid.
- `show_structure_labels=False` suppresses only validated placement/content
  metadata. Unsupported feature bits remain diagnostics and typed JSON data;
  they do not force a generic placement label into body content. Nonempty
  unknown placement/content types, invalid containers, and preservation-loss
  objects remain visible. Empty furniture remains in diagnostics/JSON without
  inventing body content. JSON always retains the structure.
- Existing native page-furniture promotion remains authoritative. Label
  suppression must not duplicate header/footer content in the body or erase a
  non-promoted container's readable text.
- PDF verification requires both extracted-text assertions and Poppler raster
  inspection. Generated PDF bytes are not a layout oracle.

## Verification

- Add canonical and malformed parser fixtures for all four table record types,
  including custom widths, header rows, alignment, a valid merge, conflicting
  merge members, unknown tails, huge integers, and sparse dimensions.
- Assert proportional widths and clean default labels in HTML, PDF, ODT, DOCX,
  Markdown, and text; assert `show_structure_labels=True` restores labels.
- Assert empty headers/footers disappear by default while nonempty fallback
  content survives.
- Re-run the complete suite, Ruff, `git diff --check`, strict-loss tests, and
  the private corpus audit.
- Convert and visually inspect at least `mydocs/6e.sam` plus one merged-table
  document with Poppler. Check for missing cells, shifted columns, clipping,
  overlaps, unwanted labels, and pagination regressions.
